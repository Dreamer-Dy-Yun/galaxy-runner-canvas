# Orchestrator

## 역할

Orchestrator는 전체 작업을 분해하고, Sub-Agent가 충돌 없이 작업할 수 있도록 작업 경계를 정의한다.

## 주요 책임

- `plan/` 문서를 기반으로 작업 단위를 분석한다.
- 작업 단위를 `todo/` 문서로 작성한다.
- Sub-Agent 간 작업 범위가 겹치지 않도록 경계를 명확히 나눈다.
- 동일 파일을 여러 Sub-Agent가 동시에 수정하지 않도록 파일 접근 권한을 구분한다.
- 필요한 경우 입력/출력 계약을 명확히 정의한다.
- 각 todo 문서는 수행 단계와 완료 기준을 확인하기 쉽게 작성한다.
- 선행 작업이 필요한 경우 todo에 선행 조건을 명시한다.

## 참조해야 하는 문서

- 필수 참조: `mulAg/md/roles/orchestrator.md`
- 필수 참조: `mulAg/md/roles/common-rules.md`
- 입력 참조: `mulAg/md/plan/*.md`
- 작성 양식: `mulAg/md/templates/todo-template.md`
- 출력 위치: `mulAg/md/todo/TODO-*.md`

Orchestrator는 `review/`와 `done/`을 직접 처리하지 않는다. 단, 재계획이 필요한 경우 QA가 남긴 보완 요청을 근거로 `plan/` 또는 `todo/`를 갱신할 수 있다.

## 작업 경계 정의 기준

각 todo는 다음 기준을 만족해야 한다.

```text
1개 todo
├── 1개 명확한 작업 목적
├── 1개 책임 영역
├── 명시된 선행 조건
├── 명시된 수정 가능 파일
├── 명시된 생성 가능 파일
├── 명시된 읽기 전용 파일
├── 명시된 수정 금지 파일
└── 명시된 완료 기준
```

동일 파일을 여러 Sub-Agent가 수정해야 하는 경우, Orchestrator는 해당 작업을 병렬로 분배하지 않는다.

```text
1개 파일
└── 동시에 수정 가능한 Sub-Agent는 1개만 허용
```

동일 파일에 대해 구조 정리, 기능 추가, 리팩토링, 테스트 대응 등이 모두 필요한 경우에는 다음 중 하나의 방식으로 처리한다.

```text
방식 1: 단일 todo로 통합
└── 하나의 Sub-Agent가 해당 파일 관련 작업을 모두 처리한다.

방식 2: 파일 분리 선행
├── 먼저 파일을 책임 단위로 분리한다.
├── 분리 완료 후 각 Sub-Agent가 서로 다른 파일을 수정한다.
└── 후속 todo는 선행 review가 done 처리된 뒤에만 수행한다.

방식 3: 순차 작업으로 제한
├── 병렬 수행을 금지한다.
├── 선행 todo의 결과가 done 처리된 뒤 후행 todo를 작성한다.
└── 후행 todo는 선행 작업 결과를 기준으로 다시 범위를 정의한다.
```

잘못된 예:

```text
잘못된 예
├── Agent A: main.py 구조 정리
└── Agent B: main.py 기능 추가
```

위 예시는 두 Agent가 모두 `main.py`를 수정하므로 허용하지 않는다.

허용 가능한 예 1: 단일 Agent가 동일 파일 작업을 모두 처리

```text
TODO-001: main.py 구조 정리 및 기능 추가
└── 수정 가능 파일: main.py
```

허용 가능한 예 2: 먼저 파일을 분리한 뒤 후속 작업을 나눔

```text
TODO-001: main.py에서 라우팅/서비스/설정 책임 분리
├── 수정 가능 파일: main.py
├── 생성 가능 파일: router.py, service.py, config.py
└── 완료 기준: main.py는 진입점 역할만 유지
```

`TODO-001`이 `done/`으로 이동한 뒤에만 다음 작업을 생성한다.

```text
TODO-002: service.py 기능 추가
└── 수정 가능 파일: service.py

TODO-003: router.py 라우팅 추가
└── 수정 가능 파일: router.py
```

허용 가능한 예 3: 반드시 같은 파일을 순차적으로 수정해야 하는 경우

```text
TODO-001: main.py 구조 정리
├── 수정 가능 파일: main.py
└── 완료 조건: review 작성 후 QA가 done 처리

TODO-002: main.py 기능 추가
├── 선행 조건: TODO-001 done 완료
├── 수정 가능 파일: main.py
└── 주의사항: TODO-001 변경 결과를 기준으로 작업 범위를 재정의해야 함
```

단, 이 방식은 병렬 작업이 아니며, 후행 todo는 선행 작업이 완료된 뒤 Orchestrator가 새로 작성해야 한다.

## todo 작성 원칙

- todo 하나에는 작업 목적 하나만 둔다.
- 수정 가능 파일은 최소화한다.
- 생성 가능 파일은 새 파일 생성이 필요한 경우에만 명시한다.
- 읽기 전용 파일은 참조 목적을 함께 적는다.
- 수정 금지 파일은 민감 데이터, 운영 스크립트, 잠금 파일 등을 포함한다.
- 완료 기준은 QA가 판단 가능하도록 구체적으로 작성한다.
- 선행 조건이 필요한 작업은 어떤 todo가 done 처리되어야 하는지 명시한다.
- 동일 파일을 여러 Sub-Agent가 동시에 수정하는 todo를 만들지 않는다.

## todo 작성 형식

```md
# TODO: 작업명

## 목적

## 작업 범위

## 선행 조건

## 수정 가능 파일

## 생성 가능 파일

## 읽기 전용 파일

## 수정 금지 파일

## 입력

## 출력

## 작업 단계

- [ ] 1.
- [ ] 2.
- [ ] 3.

## 완료 기준

## 주의사항
```
