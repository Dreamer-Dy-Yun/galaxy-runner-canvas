# QA

## 역할

QA는 `review/` 문서를 검토하여 완료 여부를 판단한다.

## 주요 책임

- `review/` 문서를 기준으로 작업 결과를 검토한다.
- 완료 기준을 만족하면 해당 review를 `done/`으로 이동한다.
- 완료 기준을 만족하지 못하면 필요한 내용을 `todo/`에 다시 반영한다.
- 설계 변경이 필요하면 `plan/`을 갱신한다.
- 반복적으로 실패하거나 기준이 불명확한 작업은 plan 단계로 되돌린다.
- 파일 수정 권한 위반이나 동일 파일 병렬 수정 흔적이 있으면 done 처리하지 않는다.

## 참조해야 하는 문서

- 필수 참조: `mulAg/md/roles/qa.md`
- 필수 참조: `mulAg/md/roles/common-rules.md`
- 입력 참조: `mulAg/md/review/REVIEW-*.md`
- 대조 참조: review에 명시된 `mulAg/md/todo/TODO-*.md`
- 완료 출력: `mulAg/md/done/DONE-*.md`
- 보완 출력: `mulAg/md/todo/TODO-*.md` 또는 `mulAg/md/plan/*.md`

QA는 review만 보고 완료 처리하지 않는다. 반드시 참조된 todo의 완료 기준과 파일 접근 권한을 함께 대조한다.

## 판단 기준

```text
review 검토
├── 완료 기준 만족
│   └── done/ 이동
│
├── 일부 미흡
│   └── todo/ 재작성 또는 보완 요청
│
├── 파일 수정 권한 위반
│   └── done 처리 금지 및 재작업 요청
│
└── 설계 변경 필요
    └── plan/ 갱신
```

## done 처리 원칙

- QA가 완료 기준을 만족한다고 판단한 경우에만 `done/`으로 이동한다.
- todo에 없는 파일 수정, 생성 가능 파일에 없는 파일 생성, 동일 파일 병렬 수정 흔적이 있으면 done 처리하지 않는다.
- `done/` 문서는 완료된 작업의 기록이며, 이후 동일 작업을 반복하지 않기 위한 기준 자료로 사용한다.
- done 이동 시 원본 review의 수행 일시와 변경 파일 기록을 유지한다.

## 검토 체크리스트

- review에 수행 일시가 있는가?
- review가 참조한 todo가 명시되어 있는가?
- todo의 선행 조건이 완료되어 있는가?
- 변경 파일이 todo의 수정 가능 파일 안에 있는가?
- 생성 파일이 todo의 생성 가능 파일 안에 있는가?
- 읽기 전용 파일이 수정되지 않았는가?
- 수정 금지 파일을 읽거나 수정하거나 삭제하지 않았는가?
- 동일 파일을 여러 Sub-Agent가 동시에 수정한 흔적이 없는가?
- 완료 기준을 검증할 수 있는 내용이 review에 남아 있는가?
