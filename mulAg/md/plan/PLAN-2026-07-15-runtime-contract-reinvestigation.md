# PLAN: 실행 순서와 모듈 계약 재조사

## 작성 일시

2026-07-15

## 목적

Galaxy Runner가 현재 배포본에서 실제로 실행된다는 사실과 별개로, 실행 성공이 정상적인 공개 계약에 기반한 것인지 특정 초기화 순서와 런타임 메서드 교체에 의존하는지 재조사한다.

조사 결과를 근거로 현재 사용 가능성, 모듈 하드닝 상태, 테스트 신뢰도를 다시 판단하고 책임 단위의 수정 계획을 만든다.

- 비교 기준: 현재 `HEAD`의 코드, 문서, 테스트 및 동일 SHA의 GitHub Pages 배포본

## 핵심 질문

1. `main.js`의 부트 순서가 각 모듈의 명시적 계약인가, 아니면 문서화되지 않은 순서 의존성인가?
2. `DebugOverlay`와 `FrameProfiler`가 `runtime.frame`을 교체하는 방식은 독립적으로 결합 가능한가?
3. 장식적 디버그 모듈의 유무나 연결 순서가 게임 실행 가능성을 바꾸는가?
4. 문서가 주장하는 엔진/게임 경계와 실제 import·상태·부작용 경계가 일치하는가?
5. 테스트가 실제 부트 조합과 순서 변경 실패를 검출하는가?
6. 현재 게임의 기획·플레이 루프·UI는 기술 부채와 분리해 어떤 수준으로 완성되어 있는가?

## 통합 판단 기준

- 실제 브라우저에서 동작한다는 이유만으로 모듈 계약이 정상이라고 판단하지 않는다.
- 비전형적인 구현이라는 이유만으로 사용자 실행 장애라고 판단하지 않는다.
- 명시적 계약, 독립 결합성, 실패 가시성, 테스트 증거, 문서 일치를 각각 판단한다.
- 주요 결론은 파일/라인 또는 실행 명령 증거와 연결한다.
- 조사 패스 간 결론이 다르면 합의된 부분과 불일치 부분을 모두 기록한다.
